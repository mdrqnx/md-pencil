# md pencil

마크다운을 깨끗하게 읽고, 그 위에 애플펜슬로 필기하는 아이패드용 웹앱.

손가락으로는 스크롤하고, 펜으로는 그립니다. 둘이 서로 방해하지 않습니다.

## 쓰는 법

1. 아이패드 Safari 로 배포 주소를 엽니다
2. 공유 버튼 → **홈 화면에 추가**
3. 홈 화면 아이콘으로 실행하면 주소창 없이 전체 화면으로 뜹니다

한 번 열어두면 다음부터는 인터넷 없이도 켜집니다.

문서 넣는 방법은 네 가지입니다.

| 방법 | 쓸 만한 때 |
|---|---|
| 파일 | 아이패드 파일 앱 · iCloud Drive 에 있는 `.md` |
| 붙여넣기 | 원문을 그대로 복사해 올 때 |
| 주소 | GitHub 파일 주소 (`blob` 주소를 넣어도 raw 로 알아서 바꿉니다) |
| 최근 | 한 번 넣은 문서는 필기와 함께 계속 남습니다 |

필기는 자동 저장됩니다. 앱을 껐다 켜도, 아이패드를 재부팅해도 그대로입니다.

## 제스처

| 동작 | 결과 |
|---|---|
| 애플펜슬로 긋기 | 필기 |
| 손가락 하나 | 스크롤 |
| 손가락 둘 벌리기 / 오므리기 | 확대 / 축소 |
| 손가락 둘로 톡 치기 | 펜 ↔ 지우개 |

**애플펜슬 더블탭은 웹앱에서 받을 수 없습니다.** 그 신호는 `UIPencilInteraction`
으로만 오고 Safari 가 웹페이지에 넘겨주지 않습니다. Pencil Pro 의 스퀴즈도 같습니다.
두 손가락 탭이 그 자리를 대신합니다 — 펜을 든 손은 그대로 두고 반대 손으로 칩니다.

외장 키보드가 있으면 `1` `2` `3` 으로 펜/형광펜/지우개, `⌘Z` 되돌리기, `⌘O` 문서 열기.

## 필압

툴바의 **필압** 칩으로 끕니다. 끄면 세기와 무관하게 늘 같은 두께로 그어집니다.
설정은 앱 전체에 하나이고 그대로 기억됩니다.

구현은 저장 형식을 건드리지 않습니다. 필압이 꺼져 있으면 모든 점의 필압을 1.0 으로
흘려보내는데, `widthAt(s, 1)` 이 정확히 `s.w` 라서 결과가 일정한 두께가 됩니다.

## 형광펜은 글자 뒤에

반투명한 형광펜을 글자 위에 얹으면 글자가 뿌옇게 뜹니다. 그래서 잉크 층을 둘로
나눴습니다 — **형광펜은 글자 뒤(`#inkUnder`), 펜은 글자 위(`#ink`).** 종이만 물들고
글자는 그대로 새까맣습니다.

층이 둘이면 타일 메모리도 둘이 되므로, 뒤 층은 **실제로 형광펜이 지나가는 타일에만**
백킹스토어를 잡습니다. 형광펜을 쓰지 않는 문서에서는 비용이 0 입니다. 첫 획을 그을
때는 아직 획이 없으니 `beginInput` 이 `forceLayer` 로 미리 붙여둡니다.

## 글자 크기와 본문 폭, 글꼴

툴바의 **가가** 버튼에서 정합니다. 글자 크기 8~20, 본문 폭 360~660px, 글꼴 4종.
전부 **문서마다 따로** 저장되고, 마지막에 고른 값이 다음에 넣는 문서의 기본값이 됩니다.

글꼴은 아이패드에 이미 들어 있는 것만 씁니다. 내려받는 웹폰트를 쓰면 첫 렌더가 늦어지고,
늦게 도착한 글꼴이 문단을 다시 흐르게 해서 필기가 어긋납니다. 다만 **iOS 에는 한글
세리프가 없습니다** — Apple SD Gothic Neo 하나뿐이라, 세리프·둥근을 골라도 한글
글자 모양은 그대로고 라틴 문자와 숫자만 바뀝니다. 고정폭은 라틴이 확실히 갈립니다.

**크기와 폭은 서로 묶여 있지 않습니다.** 폭을 글자 크기에 연동해두면 글자를 키울수록 여백이
잡아먹히는데, 그 여백이 바로 필기 공간이라 반대로 움직여야 맞습니다. 폭을 고정해두면
글자를 아무리 키워도 옆에 쓸 자리는 그대로입니다. 팝오버 아래에 왼쪽·오른쪽 여백이
몇 px 인지 같이 나옵니다.

**필기가 한 획이라도 있으면 셋 다 잠깁니다.** 무엇이 바뀌어도 문단이 다시 흐르고, 그러면
이미 그어둔 필기가 통째로 어긋나기 때문입니다. **필기를 시작하기 전에** 정해야 합니다.
다 지우면 다시 풀립니다.

폭 설정이 없던 시절의 문서는 그때 규칙(34em, 상한 624px)으로 계산한 값을 그대로
물려받습니다. 렌더 결과가 한 픽셀도 달라지지 않아야 필기가 제자리에 남습니다.

## 다른 앱에서 공유로 보내기

**아이폰·아이패드는 웹앱을 공유 시트에 올려주지 않습니다.** `share_target` 은 안드로이드
크롬만 지원하고, iOS 에는 웹앱을 다른 앱의 공유 대상으로 등록할 방법이 없습니다.
앱에서 어찌할 수 있는 부분이 아닙니다.

대신 **단축어** 를 하나 만들면 공유 시트에 뜨고, 그 단축어가 내용을 넘겨줍니다.
앱의 문서 시트 → **파일** 탭 → *다른 앱에서 공유로 보내려면* 에 순서와 주소가 있습니다.

**md 파일을 그대로 공유하면 됩니다.** 단축어는 동작 두 개면 충분합니다.

1. **입력에서 텍스트 가져오기** (Get Text from Input)
2. **클립보드에 복사** (Copy to Clipboard)

그리고 앱의 **붙여넣기** 탭에서 **클립보드에서 가져오기** 를 누릅니다.

### 주소로 여는 방법을 권하지 않는 이유

`#md=` 로 여는 길도 열어뒀지만 아이패드에서 실제로 해보면 두 군데서 막힙니다.

- 홈 화면 앱이 아니라 **Safari 로 열립니다.** iOS 는 둘의 저장 공간을 따로 쓰므로
  홈 화면 아이콘으로 연 앱에는 그 문서가 없습니다.
- 단축어의 `URL 인코딩` 이 줄바꿈을 그냥 두는 바람에 `URL 열기` 가 그것을 **여러 개의
  주소로 갈라 읽습니다.** 결과적으로 첫 줄만 들어옵니다. 굳이 쓰려면 인코딩 다음에
  **텍스트 대치**(정규 표현식)로 `\n` → `%0A` 를 하나 더 넣어야 합니다.

그래서 클립보드 쪽이 기본입니다. 주소 방식은 이렇게 씁니다.

```
https://<배포주소>/#md=<URL 인코딩된 마크다운 원문>
https://<배포주소>/#url=<가져올 주소>
```

앞에 `name=<이름>&` 을 붙이면 문서 이름을 지정할 수 있고, 없으면 첫 `# 제목` 에서
따옵니다. **`md=` 는 반드시 맨 뒤**여야 합니다 — 그 뒤로는 전부 원문으로 읽습니다.

파싱에서 남의 인코더를 믿지 않습니다. `URLSearchParams` 는 `+` 를 공백으로 되돌려
원문의 `+` 를 날리고, iOS 단축어의 URL 인코딩은 `&` 나 `#` 을 그냥 두기도 합니다.
그래서 `md` 만은 `&` 로 자르지 않고 해시 끝까지 통째로 가져옵니다.

쿼리스트링이 아니라 **해시**를 쓰는 이유는 두 가지입니다. 해시는 서버로 전송되지 않아
원문이 접속 로그에 남지 않고, 길이 여유도 더 큽니다. 그래도 아주 큰 파일은 주소 길이
한계에 걸릴 수 있습니다. 그럴 때 확실한 두 가지는 이렇습니다.

- 공유 → **파일에 저장** 한 다음 **파일** 탭에서 고르기
- 화면 분할(Split View)로 파일 앱을 옆에 띄우고 **md 를 이 창으로 끌어다 놓기**

## 백업

문서와 필기는 이 기기 안에만 있습니다. 아이패드를 초기화하거나 Safari 데이터를
지우면 되돌릴 방법이 없습니다.

문서 시트의 **최근** 탭 아래에서 **전체 내보내기** 를 누르면 공유 시트가 뜹니다.
*파일에 저장* 으로 iCloud Drive 에 넣어두세요. **백업 가져오기** 로 그대로 돌아옵니다.

Safari 탭으로만 쓰면 iOS 가 한동안 안 쓴 사이트의 데이터를 정리해버릴 수 있습니다.
홈 화면에 추가한 앱은 그 대상에서 빠지므로, 아이콘으로 쓰는 편이 안전합니다.

## 왜 어긋나지 않는가

이런 앱의 유일한 난제는 **필기와 글자의 위치가 틀어지는 것**입니다. 화면을 회전하거나
글꼴이 바뀌면 문단이 다시 흐르고, 어제 그은 밑줄이 엉뚱한 줄에 가 있게 됩니다.

md pencil 은 **마크다운을 편집하지 않는다**는 전제 위에 서 있습니다. 그래서
페이지 폭을 `PAGE_W = 900px` 로 못박고, 화면에 맞추는 일은 오직 CSS `transform: scale()`
로만 합니다. 화면을 어떻게 돌리든 문서는 다시 흐르지 않고, 한 번 정해진 필기 좌표는
영원히 유효합니다.

글자 크기·본문 폭·글꼴만이 이 전제를 깰 수 있는 조작인데, 그래서 그 셋만 필기가 없을 때로
막아둡니다. 나머지는 무엇을 하든 문서가 다시 흐르지 않습니다.

## 구조

```
index.html   화면 뼈대
style.css    본문 타이포그래피와 UI
app.js       전부 — 렌더 · 타일 · 입력 · 저장
sw.js        오프라인 캐시
lib/         markdown-it (번들해 둠, 외부 CDN 을 타지 않습니다)
```

`app.js` 안에서 알아둘 만한 부분:

- **잉크 타일** — 문서 전체를 canvas 한 장으로 덮으면 iOS 의 canvas 크기 한계에 걸립니다.
  1024px 단위로 잘라 두고, 화면에 보이는 것 ±1 장만 메모리를 잡습니다. 나머지는
  `width = 0` 으로 반납했다가 필요할 때 스트로크 벡터에서 다시 그립니다.
- **펜 판별** — `touch.touchType === 'stylus'` 일 때만 `preventDefault()` 합니다.
  손가락 터치는 건드리지 않으므로 네이티브 스크롤이 관성까지 그대로 살아 있습니다.
- **필압** — `touch.force`. 굵기에 0.55 를 바닥으로 깔아 가볍게 스쳐도 선이 끊기지 않습니다.
  꺼두면 늘 1.0 을 흘려보내 두께가 일정해집니다. 처음 몇 점(`WARM_PTS`)은 필압이
  아직 안 실려 획의 머리가 뾰족해지므로, 나중 값으로 거슬러 올라가 덮어씁니다.
- **손떨림 필터** — One Euro. 느리게 움직이면 세게 다듬고 빠르면 거의 통과시킵니다.
  일정한 세기로 걸면 빠른 획이 손을 못 따라오는데, 이쪽은 속도를 보고 조절합니다.
  실측 지연: 84px/s 에서 2.8px, 1348px/s 에서 3.9px — 화면에서는 어느 속도든
  3~4px 뒤처지는 정도라 눈에 띄지 않습니다. 손맛은 `OE_MIN_CUTOFF` 와 `OE_BETA` 로
  조절합니다.
- **삐침 제거** — 펜이 닿거나 떨어지는 순간 한 점이 튀어 삐침으로 남습니다.
  양 끝에서 "짧은데 방향이 급히 꺾이는" 점 하나를 걷어냅니다(`trimSpur`).
- **잉크 두 층** — 형광펜은 `#inkUnder`(글자 뒤), 펜은 `#ink`(글자 위). 뒤 층은 형광펜이
  지나가는 타일에만 백킹스토어를 잡습니다.
- **저장** — IndexedDB. 좌표는 0.1px 로 반올림해 넣습니다. 글자 크기·본문 폭·글꼴은
  문서 레코드의 `fs` / `cw` / `ff`. 백업에도 함께 실려 나갑니다.
- **해시 하역** — `#md=` / `#url=` 을 `URLSearchParams` 가 아니라 직접 파싱합니다.
  그쪽은 `+` 를 공백으로 되돌려서 마크다운 원문의 `+` 가 날아갑니다.

## 배포

GitHub Pages 로 올립니다. Service Worker 는 https 에서만 등록되므로,
오프라인 실행을 원하면 https 로 서빙해야 합니다.

```bash
git push -u origin main
```

그다음 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)**.
1~2분 뒤 `https://mdrqnx.github.io/md-pencil/` 로 열립니다.

## PC 에서 확인할 때

```powershell
cd C:\Projects\md-pencil
python -m http.server 8080
```

`http://localhost:8080` 에서 마우스로 그려볼 수 있습니다. 같은 와이파이의
아이패드에서 `http://<PC의IP>:8080` 으로 들어가면 실제 펜 감각을 확인할 수 있습니다.
다만 http 라서 오프라인 캐시와 홈 화면 추가는 이때 동작하지 않습니다.
